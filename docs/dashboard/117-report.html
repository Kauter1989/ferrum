2. Анализ кода и паттерны

Производное представление

Ни один статус не вводится вручную: все числа выводятся командами git — дисциплина ferrum-report §3. План остаётся единственным источником правды; дашборд не может разойтись с ним по построению.

Чтение ревизий, а не рабочего дерева

git show <rev>:dev_plan.md, git grep … <rev>, git merge-base --is-ancestor. Штампа «время генерации» нет: meta.generated_at — дата целевого коммита (%cI), детерминизм не нарушается настенными часами.

PR-ancestry по subject (фикс ревью)

Мержи ищутся по теме коммита (^Merge pull request #N / squash (#N)$) через --all; упоминание issue в теле — не мерж; release-only мерж виден тегу, даже если не виден цели. На реальном плане это убрало ложные done-маркеры с docs-коммитов, упоминающих #70.

Отказ вместо угадывания (L37)

Неизвестный маркер, пустая ячейка критериев, отсутствующий тег — именованный meta.warnings и unknown, никогда молчаливый fallback. На реальном плане 0 предупреждений; фикстуры проверяют каждый отказ.
