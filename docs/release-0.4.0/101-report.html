1. Архитектурные изменения

Релиз 0.4.0 готовился по состоянию репозитория: develop на 167 коммитов впереди main (0.3.0). Подготовка закрывает три вещи: коллизию ADR 0011 между ветками, отсутствие главного анонса релиза (WebGPU-панели) в архивах, и дефект view serve, найденный собственной проверкой в песочнице.

Связи

Сплошные стрелки — поток сборки и запроса; пунктир — отказ границы и происхождение модуля панели. Резолвинг workspace — тот же метод, что у всех агентских команд.

Слоистость

  • ferrum-cli только парсит аргументы и вызывает существующий метод конфигурации — бизнес-правило осталось в ferrum-agent (CLAUDE.md: «ferrum-cli only parses arguments»).
  • ferrum-view не изменён: раздача /panel/… и токен — как прежде; архив лишь кладёт файлы туда, откуда хост их читает.
  • Правило рендеринга не затронуто: шейдеры и CPU-эталон не менялись, панель использует тот же volume.wgsl.
  • Контрактные поверхности: набор агентских команд, протокол движка, формат workspace — без изменений (схема commands.json свежая, проверено).

2. Анализ кода и паттерны

Единая точка правила (fix)

Дефект: view serve передавал сырую строку workspace в Session::open, минуя data.workspace_root — относительные имена не работали из произвольного каталога, а workspace вне root не отказывался. Фикс вызывает тот же resolve_workspace, что и все агентские команды: 

let workspace = match config.resolve_workspace(std::path::Path::new(&ws.workspace)) {
    Ok(path) => path,
    Err(e) => {
        println!("{}", ferrum_agent::envelope::error_envelope(&e));
        return ExitCode::from(1);
    }
};
return view_serve(&workspace, port, cpu);

Отказ — envelope с кодом forbidden, как у check_source; лексическая нормализация закрывает .. и префиксные трюки. Известное ограничение (S2, не введено этим PR): граница лексическая, symlink/junction внутри root может указывать наружу — общее для всех команд, вынесено в backlog.

Версия bindgen привязана к lockfile

Шаг taiki-e/install-action@v2 ставит wasm-bindgen-cli@0.2.129 — ровно версия wasm-bindgen в Cargo.lock и в build.cmd; дрейф версий кодогенерации закрыт. Сборки идут с --locked.

Тесты, которые не могут не упасть

МутацияЧто падает
Вернуть сырую строку в view_serve (откат фикса)a_relative_workspace_is_resolved_below_the_root (ошибка не содержит root-путь) и a_workspace_outside_the_root_is_refused (нет envelope)
Убрать лексическую нормализациюa_lexical_escape_through_the_root_is_refused (ws/../../outside перестал бы отказываться)

3. Этапы ревью

Ревью до пуша: security-reviewer (субагент, полный статический разбор) + адверсариальная перечитка диффа ведущим агентом. code-reviewer-субагент трижды завершился без результата (инфраструктурный сбой, находок не вернул) — это зафиксировано; его роль выполнена ведущим агентом вручную. После ревью — коммит фиксов cb43590, бейдж покрытия 5827615, повторные fmt/clippy/тесты зелёные.
