1. Что и зачем

FERRUM получает PACS-клиент: DicomWebRepository over QIDO-RS (query) + WADO-RS (retrieve) в ferrum-io на dicom-web 0.6. Repository fit без изменения trait: path-based VolumeRepository.scan читает PathBuf как PACS URL (dicomweb://host/root?PatientID=…, dicomwebs://=HTTPS); non-URL → NothingFound (компонуется с file readers). load retrieves WADO Part 10 объекты → тот же SliceHeader/group/order/assemble_with/LPS pipeline что files (in memory, не spooling на диск).

G2 design: ADR 0021 (PACS client + send-off boundary: STOW/C-MOVE/C-STORE host-only, не agent; Orthanc AGPL отдельный сервис, не линкуется) + docs/dicomweb.md. dicom-web MIT OR Apache-2.0; cargo deny licences ok.
Windows build caveat: dicom-web reqwest использует rustls-with-aws-lc-rs → aws-lc-sys компилирует AWS-LC из C. На этой Windows машине build падает под cargo (MSVC D8050, Касперский вмешивается в child processes, L39 family); Linux/WSL/CI собирают чисто. Environmental, не дефект клиента; задокументировано в docs/dicomweb.md + L52. Windows desktop build может потребовать Kaspersky exclusions или newer MSVC (не верифицировано); ureq/ring transport — возможная альтернатива later.
