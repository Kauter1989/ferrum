1. Архитектурные изменения

Задача — #74 (P1, Demo 3 харнесса): Medical Harness обезличивает свободный текст перед моделью/логом/отчётом. FERRUM знает настоящие идентификаторы исследования и говорит, где они в тексте, — позиции и виды, никогда значения. Библиотечный API, не команда агента: модель не должна иметь возможности проверять угаданные имена против идентификаторов пациента.

2. Анализ кода и паттерны

Одна каноническая форма вместо двух алфавитов

Текст и компоненты имени сворачиваются в один канонический нижний регистр: кириллица транслитерируется в латиницу с диграфами (х→kh, ж→zh, щ→shch, ю→yu, я→ya, ь/ъ→∅), латинская диакритика снимается до базовой буквы (MÜLLER→muller), комбинирующие знаки отбрасываются (İ→i), диграф yo канонизируется в e — поэтому «Пётр», «Петр», "Petr" и "Pyotr" встречаются в одной форме. Каждый свёрнутый символ несёт байтовый диапазон оригинала, поэтому спаны — точные байтовые офсеты исходного текста. 

struct Folded { ch: char, start: usize, end: usize }  // identifiers.rs:83
fn fold(text: &str) -> Vec<Folded>                    // :91 (yo→e проход)
fn fold_char(c: char) -> Vec<char>                    // :120 (диакритика)

Толерантность с перекосом в recall

Компонент матчится как слово или как основа (минус до двух последних букв, минимум три) плюс до трёх букв — склонения «Иванова/Иванову/Ивановым»; короткие компоненты (≤4) работают как префиксы («Li» маскирует и «Liu» — закреплено unit-тестом). Пары/тройки компонентов в любом порядке (инъективное назначение с бэктрекингом — «Ivanovich Ivan Ivanov» даёт один спан), инициалы до и после фамилии, точки инициалов входят в спан. Пересечения сливаются в один спан: «Ivanov I. Ivan» не оставляет given name незамаскированным, дата поверх инициалов не оставляет год.

Даты из DICOM YYYYMMDD

8 числовых форматов в паддированном и непэддированном виде («1.1.1970» — самое частое русское написание) плюс «D месяц YYYY», «месяц D YYYY» и варианты с запятой, с паддированным и непэддированным днём — английские и русские названия месяцев (именительный и родительный). Поиск с границами слов.

Границы и стоимость

  • Значения каппятся на VR-максимумах DICOM в ридере (PN 64/компонент, LO 64, SH 16, DA 8): крафченный multi-MB patient_id больше не превращает per-text скан в минуты CPU (проверено ревьюером: 40k символов → 49 с до фикса).
  • Значение длиннее текста — ранний выход; пустые идентификаторы (NIfTI) — пустой результат; ошибки не эхо-ят значения.
  • Записанные файлы не читаются → fail closed: ни один файл не прочитан → ошибка, не пустые идентификаторы.

Что проверено как чистое (обоими агентами)
  • Байтовые офсеты — валидные границы символов оригинала: кириллица, emoji-ZWJ, комбинирующие знаки, диграфы, турецкий İ — срезы не паникуют.
  • Крафченные заголовки: non-UTF8 под ISO_IR 192 (октал-эскейпы dicom-rs), разделители/контрольные символы, 60k и 1 MiB значения — без паник.
  • Не-команда: COMMANDS, mcp::tools(), commands.json (36 ключей), schema.rs, ferrum-cli не тронуты.
  • Нет новых зависимостей, unsafe, subprocess, сети, секретов; ошибки несут пути, не значения идентификаторов.
  • Слоистость, матрица, CHANGELOG под [Unreleased] (L43), размер M.

Остаточные риски (названы)

  • TOCTOU подмена ссылки между проверкой и чтением и hard links — документированный остаток #82 (нужен доступ записи к корню данных).
  • Матчер best-effort/recall-biased: необычные склонения, письменности и форматы остаются незамаскированными; чистый скан — не гарантия де-идентификации.
  • Транскрипция («Джейн»↔"Jane") вне scope — только транслитерация; over-masking коротких компонентов — безопасное направление.
  • verify_sources хеширует серию на каждый скан — стоимость названа; кэш спанов/идентификаторов — follow-up для харнесса.
