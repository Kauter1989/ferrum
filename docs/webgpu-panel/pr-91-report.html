1. Архитектурные изменения

Задача: в харнессе для медицины показать исследование в реальном времени — вращать объём, листать срезы — не отправляя картинку, а выполняя рендерер на стороне клиента. Ядром остаётся существующий ferrum-render; вся работа — это две новые обёртки вокруг него и один плагин.

Связи

Сплошная стрелка — вызов в процессе; пунктир — связь через сокет или файл. И ferrum-wasm, и хост-рендер, и десктоп идут в ferrum-render — второго формирования изображения нет.

Ключевое свойство: ferrum-render — единственный владелец модели формирования изображения. И wasm, и десктоп, и CPU-эталон хоста идут через него. В ferrum-wasm нет ни одного .wgsl и ни одного include_str! — проверено.

Слоистость

  • ferrum-view — только ferrum-cli. Проверено: других зависимых нет.
  • ferrum-wasm — никто не зависит; нативный cargo check --workspace компилирует пустой крейт благодаря #![cfg(target_arch = "wasm32")].
  • Плагин не запускает процесс (браузерный бандл не может) — хост поднимает человек через CLI.

2. Анализ кода и паттерны

Порт вместо ветвления по платформе

ferrum-view объявляет trait FrameSource с двумя реализациями — GpuFrameSource и CpuFrameSource. Выбор делается при открытии сессии (BackendPreference), а не внутри рендера. Это тот же приём, что SegmentationEngine в ядре: интерфейс в одном месте, реализации компонуются при сборке. 

pub trait FrameSource: Send   // frame.rs
impl FrameSource for CpuFrameSource   // cpu.rs
impl FrameSource for GpuFrameSource   // gpu.rs

Тонкая обёртка вместо второй реализации

ferrum-wasm держит VolumeRenderer, OrbitCamera, TransferFunction и brick_classifier из ядра. Собственная логика — только две вещи, которых в ядре нет: раскладка MPR по четвертям и имена режимов. Обе вынесены в отдельные модули вне wasm-гейта, чтобы их можно было проверить на хосте — это решение появилось после ревью и оказалось плодотворным.

Валидация на границе

Mode::parse и set_render_mode принимают строку и возвращают ошибку с указанием значения. Это исправление дефекта F1: раньше set_mode принимал enum, а вызывающий код конвертировал строку тернарником — любое иное значение молча рисовало 2D-срез.

Где паттерны уместны, а где нет

  • Уместно: порт FrameSource — две настоящие реализации, выбор в одной точке.
  • Уместно: валидация на границе с ошибкой, называющей значение.
  • Спорно: CPU-оверлей в ferrum-view/src/cpu.rs — третья копия правила slice.wgsl (после шейдера и пути агента). Паритетного теста нет. Вынесено в follow-up: это консолидация через три крейта, ей нужен отдельный PR с кейсом в gpu_parity.rs.
  • Правильно: никакой бизнес-логики в плагине — он только передаёт намерения хосту и рендереру.

Тесты, которые не могут упасть

Самая содержательная находка ревью: тест MPR проверял не геометрию, а наличие подстрок (body.count("Vec2::new(") >= 7). Мутация — удаление аспект-фита — не роняла его. После исправления геометрия вынесена в layout.rs и проверяется настоящими числами; мутации ловятся:

МутацияРезультат
Убрать аспект-фит, как в старом тестепадает (проверено и мной, и ревьюером)
Поменять ветви фита местамипадает 4 из 6
Убрать центрированиепадает 3 из 6
Вернуть тернарник в stand.htmlпадает тест панели
Ok(Mode::Slice) вместо отказападает 3 теста

Замечания ревью #91 по существу

УровеньЗамечаниеРешение и причина
blocking Курсоры MPR сеются размерами объёма, а не серединой — срезы в конце Отклонено. В коде dims/2; для 512×512×252 это [256, 256, 126] — середина. Проверил арифметикой, а не чтением. Ложная находка; в PR записано прямо.
should-fix Два теста не могут упасть (26.2-a, панель) Исправлено. Геометрия в layout.rs с host-тестами; мутационно проверено.
should-fix Правки под Windows ослабили тесты (path_rules, package.rs) Исправлено. Проверяются оба написания ..; CRLF ловится, а не нормализуется молча.
should-fix CPU-оверлей — третья копия правила slice.wgsl Отложено осознанно. Консолидация через три крейта требует ADR-уровня и кейса в gpu_parity.rs; в конце XL-PR это скрыло бы риск.
should-fix 26.4-b проверяет подстроки, а не поведение Открыто, названо. Поведение проверено вручную против живого хоста; автоматизация требует вынести гейты в константы.
should-fix 25.4-a pixelOf без теста Открыто, названо. Сначала находка вообще потерялась из PR — дописал после вопроса пользователя.
nit Мёртвые camera_angles/describe_voxel, mojibake 512?256, устаревший список экспортов, нет перевода строки Исправлено всё. Механические правки, не требующие обсуждения.

Security-ревью

УровеньЗамечаниеРешение
low Access-Control-Allow-Origin: * на всех ответах, включая 401 — любая страница могла определять наличие хоста Исправлено. Заголовок только на 2xx; тест падает при возврате регрессии.
medium Токен один, долгоживущий, без ротации и ограничения частоты Отложено. Это дизайн loopback-хоста из ADR 0017; смена меняет протокол и требует нового ADR, а не правки в конце PR.
Что проверено как чистое (security)
  • /panel/* отдаёт только два литеральных имени файла из фиксированных каталогов — обхода путей нет, проверено тестом.
  • Хост только читает: Session::open не вызывает save/append_audit/log.
  • Привязка к 127.0.0.1, слушатель отвергает не-IP адрес.
  • Токен сравнивается за постоянное время, не логируется, требуется всеми данными-маршрутами.
  • Ни одного идентификатора пациента в /api/state, /api/events, кадрах, /api/volume.json.
  • Новые зависимости — MIT/Apache-2.0, в deny.toml.

Ревью исправления F1 (PR #92)

Баг нашёлся уже после мерджа — при ручной проверке работоспособности, которой потребовал пользователь. Ревью исправления нашло, что первая версия была неполной: две точки вызова исправлены, третья (stand.html) осталась и стала бросать необработанное исключение. Причина в том же: тест читал только бандл. Теперь тест обходит каждую страницу, вызывающую set_mode.
