1. Архитектурные изменения

Задача — #82 (P1, безопасность): операторская граница чтения data.read_roots обходилась симлинком внутри корня, а обход дерева источников следовал за ссылками без ограничений глубины и числа записей. Нашёл Medical Harness при встраивании ferrum-agent v0.3.0; харнесс прикрывает свои вызовы собственной проверкой, но FERRUM без этой обвязки был открыт. Это defence in depth.

Связи

Граница чтения замкнута в двух местах: каноническое сравнение возвращаемой нотации (agent) и ограниченный обход без следования ссылкам (io).

Слоистость

  • ferrum-domain остаётся без I/O: Limit(String) — чистый вариант ошибки порта; исчерпывающих match по RepositoryError в workspace нет (проверено grep'ом по всем крейтам).
  • Файлы по-прежнему разбираются только в ferrum-io; collect_files — единственная реализация обхода, лимиты живут в ней, а не в адаптерах.
  • Проводной контракт не изменён: код limit уже существовал в конверте ferrum-agent/1; команды, схемы, протокол движков, формат workspace и шейдеры не тронуты (commands.json свежий, package-тесты зелёные).

2. Анализ кода и паттерны

Проверяй то, что открываешь

Первый драфт проверял OS-порядок резолва, а возвращал лексическую нотацию — ревью нашло расхождение за симлинком, указывающим глубже своей нотации. Финал: канонизируется ровно та нотация, которую вернёт функция и откроет ридер; .. остаётся лексическим (контракт absolute), поэтому проверенный и открытый путь не могут разойтись. 

let abs = absolute(path)?;          // лексическая нотация — её и откроют
let real = real_path(&abs)?;        // её каноническая форма
if roots.iter().filter_map(|r| real_path(r).ok()).any(|r| real.starts_with(r)) {
    return Ok(abs);                 // проверено == открыто
}

Fail-closed на границе

real_path канонизирует глубжайший существующий предок (NotFound — подъём вверх), хвост применяет лексически на базе без симлинков; любая ошибка кроме NotFound — отказ. Корень, который не резолвится, не даёт ничего. Drive-relative пути (C:foo) на Windows отказываются: их резолвер нормализует .. лексически и скрыл бы ссылку.

Явный отказ вместо молчаливой обрезки (L37)

Превышение глубины или числа записей — RepositoryError::Limit с путём и пределом в сообщении, до конверта как limit. Обход не «усекает тихо» и не падает на петле из ссылок: обнаруженные симлинки пропускаются, петля завершается.

Где паттерны уместны, а где нет

  • Уместно: каноническое сравнение на границе оператора; единый ограниченный обход в io; аддитивный вариант ошибки порта вместо строкового хака.
  • Спорно: лексический .. может удивить (OS-порядок дал бы другой результат за ссылкой) — но это существующий контракт absolute, и теперь он честен: что проверено, то и открыто. Альтернатива (возвращать канонический путь) ломала бы формат путей в workspace на Windows (verbatim \\?\).
  • Не делалось: TOCTOU-окно между проверкой и чтением и hard links — остаточные риски, требуют прав записи в корень данных, задокументированы в issue и docs.
